# Zona Cero staging release runbook

This runbook is for the Cloudflare staging release of the API, Telegram webhook, and Web UI. Do not paste real secrets into committed files, shell history, or chat.

## Local gates

Run from the repository root before touching Cloudflare:

```sh
pnpm test:strict
pnpm web:build:staging
```

`web:build:staging` builds `apps/web-ui/dist` with:

- `VITE_API_BASE_URL=https://zona-cero-api-staging.jauss.workers.dev`
- `VITE_INCIDENT_ID=incident-zc-demo`
- `VITE_CELL_ID=cell-zc-demo`

## API staging release

The root scripts delegate to the `@zona-cero/api` workspace and use its existing Wrangler dependency.

### Telegram token source

`TELEGRAM_BOT_TOKEN` and `TELEGRAM_WEBHOOK_SECRET_TOKEN` come from different places:

| Secret | Source | What it is used for |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Telegram `@BotFather` | Authorizes Zona Cero to call the Telegram Bot API, including `sendMessage`. |
| `TELEGRAM_WEBHOOK_SECRET_TOKEN` | Generated by us | Lets the API reject webhook requests that were not sent with the expected Telegram webhook header. |

To get `TELEGRAM_BOT_TOKEN`:

1. Open the official Telegram `@BotFather` chat.
2. Send `/newbot` for a new staging bot, then follow BotFather's name and username prompts.
3. Copy the authentication token BotFather returns.
4. If the token is lost or compromised, use BotFather's `/token` command to generate a replacement.

To generate `TELEGRAM_WEBHOOK_SECRET_TOKEN`, create a random token locally. Telegram accepts 1-256 characters using `A-Z`, `a-z`, `0-9`, `_`, and `-` for `secret_token`.

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
```

Use the exact same generated value in both places:

- Cloudflare Worker secret: `TELEGRAM_WEBHOOK_SECRET_TOKEN`
- Telegram `setWebhook` parameter: `secret_token`

References:

- Telegram BotFather creates bot authentication tokens: <https://core.telegram.org/bots/features#botfather>
- Telegram `setWebhook.secret_token` sends `X-Telegram-Bot-Api-Secret-Token`: <https://core.telegram.org/bots/api#setwebhook>

Configure required staging secrets interactively before deployment. Do not pass secret values as command arguments.

```sh
pnpm --filter @zona-cero/api exec wrangler secret put TELEGRAM_BOT_TOKEN --env staging
pnpm --filter @zona-cero/api exec wrangler secret put TELEGRAM_WEBHOOK_SECRET_TOKEN --env staging
```

Keep `TURNSTILE_ROLLOUT=observe` for staging until the real Web UI widget is wired and smoke-tested.

```sh
pnpm api:migrate:staging
pnpm api:seed:staging
pnpm api:deploy:staging
```

Expected API base URL:

```text
https://zona-cero-api-staging.jauss.workers.dev
```

## Web UI Pages Direct Upload

Cloudflare Pages project:

```text
zona-cero-web-ui-staging
```

Build and deploy to the `staging` branch:

```sh
pnpm web:deploy:staging
```

That script builds `apps/web-ui/dist` and then runs Wrangler Pages Direct Upload via the existing API workspace dependency:

```sh
pnpm --filter @zona-cero/api exec wrangler pages deploy ../../apps/web-ui/dist --project-name zona-cero-web-ui-staging --branch staging
```

## Telegram webhook

Use ephemeral shell variables. Never commit or print token values. The webhook secret must match the Cloudflare Worker secret `TELEGRAM_WEBHOOK_SECRET_TOKEN`.

Run this only from a trusted local terminal with shell tracing disabled (`set +x`). Do not run it on shared hosts, recorded terminals, CI logs, or any environment where process arguments may be visible to other users.

```sh
read -rsp "Telegram bot token: " TELEGRAM_BOT_TOKEN; echo
read -rsp "Telegram webhook secret token: " TELEGRAM_WEBHOOK_SECRET_TOKEN; echo
curl -sS -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  -d "url=https://zona-cero-api-staging.jauss.workers.dev/telegram/webhook" \
  -d "secret_token=${TELEGRAM_WEBHOOK_SECRET_TOKEN}"
curl -sS "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getWebhookInfo"
unset TELEGRAM_BOT_TOKEN TELEGRAM_WEBHOOK_SECRET_TOKEN
```

## Smoke checklist

- API health/basic contract smoke returns expected staging responses.
- Telegram `/start` can select `incident-zc-demo`, join, and receive a clear confirmation.
- Telegram operational flows still return stable user-facing errors for denied/rate-limited cases.
- Web UI loads from the Pages staging URL and points to `https://zona-cero-api-staging.jauss.workers.dev`.
- Web UI can show the demo incident/cell and complete the critical Slice 3-8 happy paths that are enabled for the web channel.
- No response, log, or screenshot exposes Telegram tokens or sensitive private-link material.

## Rollback notes

- API Worker: use Wrangler deployment/version rollback for `zona-cero-api-staging` if the deployed Worker regresses.
- D1: prefer restoring from a known backup/export or applying a forward corrective migration; do not manually edit production-like staging data without recording the command and reason.
- Pages: redeploy the last known-good build artifact or previous Git revision to `zona-cero-web-ui-staging` on branch `staging`.
- Telegram: if the webhook is bad, point it back to the last known-good API URL or temporarily delete the webhook while investigating.
- D1 destructive rollback should use Cloudflare D1 backup/time-travel recovery or a reviewed forward migration, not ad-hoc reverse SQL.
